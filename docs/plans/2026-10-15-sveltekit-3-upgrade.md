# SvelteKit 3 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `apps/web` from SvelteKit 2.70.3 to SvelteKit 3.x and adapter-node 5.5.7 to 6.0.0, with no visible change for users or authors.

**Architecture:**
- Run the official migration tool (`sv migrate sveltekit-3`) and commit its output on its own.
- Then fix by hand what it can't do: tsconfig fallout, deprecated APIs, and the test mock path.
- Then add one behavioural guard: Sentry receives only real crashes.
- Finally, prove the production server (adapter-node 6) handles the site origin correctly. CI's e2e runs the dev server and cannot show this.

**Tech Stack:** SvelteKit 3, adapter-node 6, Svelte 5.57, Vite 8.3, TypeScript 6, vitest 5 (browser + node projects), Playwright 1.64, Docker Compose.

**Spec:** `docs/specs/2026-10-15-sveltekit-3-upgrade-design.md`.

## Global Constraints

- `@sveltejs/kit`: newest 3.x that is at least 7 days old at install time. pnpm enforces this with `minimumReleaseAge: 10080` in `pnpm-workspace.yaml`. On 2026-10-15 that is `3.0.1`; `3.1.0` is allowed from 2026-10-21.
- `@sveltejs/adapter-node`: `6.0.0`.
- Do not change the versions of `svelte`, `vite`, `@sveltejs/vite-plugin-svelte`, `typescript`, or Node 24.
- `$lib` imports become `#lib` (owner decision). Do NOT use the deprecated `alias: { '$lib': 'src/lib' }` escape hatch.
- Do not set `paths.origin` or `PROTOCOL_HEADER` in any committed file. adapter-node derives the origin from the `host` header and defaults the protocol to `https`.
- `ORIGIN` stays in `infra/compose.yaml` and `infra/compose.prod.yaml`, because `src/lib/server/api.ts` reads it.
- Sentry `Sentry.init` keeps every `dataCollection` category off, exactly as today (pinned by `src/hooks.server.test.ts`).
- No user-visible change: the look, copy and behaviour stay as they are.
- No test may be weakened. Any edit to an assertion must keep its meaning. Watch for `.not` checks that would pass vacuously (vitest 5: `toHaveTextContent` is exact, `toMatchTextContent` is partial).
- Never read, create or edit any file whose name starts with `.env`. Never print secret values.
- Do not commit `apps/web/MIGRATION_TASKS.md` (the tool's report) or anything under `.superpowers/`.
- Commit trailer: `Co-Authored-By: <your model name> <noreply@anthropic.com>`.
- Stay on branch `deps/sveltekit-3`. Never switch branches.

### Task 2: Sentry reports only real crashes

In SvelteKit 3 the server `handleError` hook runs for every error. Its input is `{ kind, error, event }`, where `kind` is one of:
- `'app'`: our own `error(...)` calls;
- `'framework'`: errors SvelteKit makes, such as a missing route (404);
- `'unknown'`: a thrown crash;
- `'validation'`: remote functions, which we don't use.

Only `'unknown'` may reach Sentry.

**Files:**
- Modify: `apps/web/src/hooks.server.ts` (the `handleError` export at the end of the file)
- Test: `apps/web/src/hooks.server.test.ts`

**Interfaces:**
- Consumes (from Task 1):
  - `handleError: HandleServerError` exported from `src/hooks.server.ts`;
  - the env mock already at the top of `src/hooks.server.test.ts`. Reuse it; do not declare a second one.
- Produces: nothing new.

- [ ] **Step 1: Write the failing test**

Append this `describe` block to the end of `apps/web/src/hooks.server.test.ts`. Keep the existing mocks and the existing `describe` as they are.

```ts
describe('hooks.server handleError', () => {
	// SvelteKit 3 runs handleError for every server error, tagged with `kind`. Only a real crash
	// ('unknown') goes to Sentry: our own error(404)s ('app') and SvelteKit's missing-route 404s
	// ('framework') are expected and would only be noise.
	it('reports only unknown (crash) errors to Sentry', async () => {
		const Sentry = await import('@sentry/sveltekit');
		const { handleError } = await import('./hooks.server');
		const event = {} as Parameters<typeof handleError>[0]['event'];
		const crash = new Error('boom');

		await handleError({ kind: 'app', error: { message: 'Not found' }, event });
		await handleError({ kind: 'framework', error: { status: 404, message: 'Not Found' }, event });
		expect(Sentry.captureException).not.toHaveBeenCalled();

		await handleError({ kind: 'unknown', error: crash, event });
		expect(Sentry.captureException).toHaveBeenCalledExactlyOnceWith(crash);
	});
});
```

The `.not.toHaveBeenCalled()` is not vacuous. It runs after two real `handleError` calls, and today's hook would forward both. vitest 5 clears mock history before each test, so the first `describe`'s import doesn't leak calls in.

- [ ] **Step 3: Implement the filter**

In `apps/web/src/hooks.server.ts`, replace the final `handleError` block. Today's code is:

```ts
// Reports unhandled server-side exceptions to Sentry when configured; a no-op when
// SENTRY_DSN is unset (falls back to SvelteKit's default { message } error shape either way).
```

```ts
// Reports real crashes (kind 'unknown') to Sentry when configured. SvelteKit 3 also calls this
// for our own error(...)s ('app') and its own 404s ('framework'); those are expected and skipped.
// A no-op when SENTRY_DSN is unset (SvelteKit's default { message } error shape either way).
export const handleError: HandleServerError = ({ kind, error }) => {
	if (env.SENTRY_DSN && kind === 'unknown') Sentry.captureException(error);
};
```
